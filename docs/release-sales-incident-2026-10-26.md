# Daily record-sale outage and Shockmaster recovery — 2026-10-26

## Incident and impact
Daily sales recorded no new release_sales rows after 2026-10-13. The active pg_cron task `generate-daily-sales` was reporting successful HTTP dispatch, but Edge responded with HTTP 401 because the job still used a baked-in anon bearer incompatible with privileged auth. Shockmaster's **I'm sorry  if your living** was released with manufactured digital/CD/vinyl/cassette formats on 2026-10-21 and consequently had zero sales.

## Production work performed
- Updated pg_cron job 18 to use the Vault `internal_cron_secret` header only, removing the literal JWT. This directly changed production DB metadata.
- Deployed `generate-daily-sales` Edge Function version 453 with trusted scheduler authentication, then manually executed. The invocation inserted 145 sale rows for Shockmaster's album before exhausting worker compute resources (HTTP 546), **before** paying band and label.
- Atomically reconciled that partial run on 2026-10-26 by writing a `daily_release_sales_claims` recovery receipt and both band earnings and label finance transactions, using existing cents-based sales splits. Marked interrupted job failed. **Do not replay this one-off recovery operation.**
- Album ledger: 656,797 copies; gross sale facts 763,287,203 minor units; band allocation 384,696,775 minor units; label allocation 256,464,460 minor units. Paid band $3,846,967, with 75 minor units in its fractional carry. Its balance became $8,188,725 immediately after recovery.
- Deployed a one-release-per-invocation version 454 with per-song fame aggregation to prevent worker compute exhaustion. Verified manual test: one release, 125,227 units, HTTP 200, zero errors, band and label credited.
- Revised pg_cron job 18 to run every 10 minutes to process remaining released records without replay.

## Monitoring and follow-up
Check `cron.job`, `cron.job_run_details`, `cron_job_runs`, `daily_release_sales_claims`, `release_sales`, `band_earnings` and `label_financial_transactions`. Failed/processing claims require manual review against actual sale/finance rows; do not automatically retry, to avoid double payments.

**Historical caveat:** This recovery did not invent or book individual lost dates between 2026-10-14 and 2026-10-25. Existing 2026-10-26 entries were generated by the resumed daily simulator, not historic backfill.
